# gRPC Status Metrics Filter

## Overview

The gRPC Status Metrics filter is a custom HTTP filter for Envoy that automatically detects gRPC requests and extracts gRPC status codes from upstream responses. It exposes these status codes as metric dimensions, allowing for detailed monitoring and observability of gRPC services.

## Features

- **Automatic gRPC Detection**: Automatically detects gRPC requests based on content-type headers
- **Status Code Extraction**: Extracts gRPC status codes from response headers and trailers
- **Flexible Metrics**: Configurable metric prefixes and selective success metric emission
- **HTTP Correlation**: Optional inclusion of HTTP status codes for correlation
- **Service/Method Granularity**: Optional service and method name dimensions (use with caution due to cardinality)

## How It Works

1. **Request Detection**: The filter examines incoming request headers to detect gRPC requests using `Grpc::Common::isGrpcRequestHeaders()`
2. **Response Processing**: For detected gRPC requests, the filter processes response headers and trailers
3. **Status Extraction**: Extracts gRPC status codes using `Grpc::Common::getGrpcStatus()`
4. **Metric Recording**: Records status codes as individual counter metrics

## Configuration

```yaml
name: envoy.filters.http.grpc_status_metrics
typed_config:
  "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_status_metrics.v3.FilterConfig
  metric_name_prefix: "grpc_status"        # Optional: Custom metric prefix
  emit_success_metrics: true               # Optional: Include success (status=0) metrics
  include_http_status: false               # Optional: Include HTTP status as dimension
  include_service_method: false            # Optional: Include service/method names (HIGH CARDINALITY!)
```

### Configuration Parameters

- **`metric_name_prefix`** (string, optional): Prefix for all metrics generated by this filter. Default: "grpc_status"
- **`emit_success_metrics`** (bool, optional): Whether to emit metrics for successful gRPC calls (status code 0). Default: true
- **`include_http_status`** (bool, optional): Whether to include HTTP status code as additional metric dimension. Default: false
- **`include_service_method`** (bool, optional): Whether to include gRPC service and method names as metric dimensions. **Warning**: This can significantly increase metric cardinality. Default: false

## Usage Examples

### Basic Configuration

```yaml
http_filters:
- name: envoy.filters.http.grpc_status_metrics
  typed_config:
    "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_status_metrics.v3.FilterConfig
    emit_success_metrics: true
```

### Error-Only Monitoring

```yaml
http_filters:
- name: envoy.filters.http.grpc_status_metrics
  typed_config:
    "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_status_metrics.v3.FilterConfig
    metric_name_prefix: "grpc_errors"
    emit_success_metrics: false  # Only track error status codes
```

### With HTTP Correlation

```yaml
http_filters:
- name: envoy.filters.http.grpc_status_metrics
  typed_config:
    "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_status_metrics.v3.FilterConfig
    include_http_status: true  # Include HTTP status for correlation
```

## Monitoring and Alerting

You can use these metrics for:

1. **Error Rate Monitoring**: Alert on increases in error status codes (4-16)
2. **Service Health**: Monitor overall success rates using status_0 vs total
3. **Performance Debugging**: Correlate gRPC status with HTTP status when `include_http_status` is enabled
4. **Capacity Planning**: Track total gRPC request volume

Example Prometheus queries:

```promql
# gRPC error rate
sum(rate(grpc_status_grpc_status_4[5m])) by (cluster) + 
sum(rate(grpc_status_grpc_status_5[5m])) by (cluster) + 
sum(rate(grpc_status_grpc_status_13[5m])) by (cluster) + 
sum(rate(grpc_status_grpc_status_14[5m])) by (cluster)

# gRPC success rate
sum(rate(grpc_status_grpc_status_0[5m])) by (cluster) / 
sum(rate(grpc_status_grpc_requests_total[5m])) by (cluster)
```

## Implementation Details

- **gRPC Detection**: Uses Envoy's built-in `Grpc::Common::isGrpcRequestHeaders()` for reliable gRPC detection
- **Status Extraction**: Leverages `Grpc::Common::getGrpcStatus()` to extract status from headers/trailers
- **HTTP Fallback**: If no gRPC status is found, the filter can infer status from HTTP response codes
- **Thread Safety**: Filter instances are per-request, ensuring thread safety
- **Performance**: Minimal overhead - only processes detected gRPC requests

## Building and Integration

1. Add the filter to your Envoy build:
   ```python
   # In source/extensions/filters/http/BUILD
   "//source/extensions/filters/http/grpc_status_metrics:config",
   ```

2. Include the protobuf configuration:
   ```python
   # In api/BUILD files  
   "@envoy_api//envoy/extensions/filters/http/grpc_status_metrics/v3:pkg_cc_proto",
   ```

3. Register in your extension list if using custom builds

## Security Considerations

- **Cardinality Control**: Be cautious with `include_service_method` as it can create high-cardinality metrics
- **Resource Usage**: Monitor memory usage when processing high-volume gRPC traffic
- **Access Control**: Ensure metric endpoints are properly secured in production

## Limitations

- Currently supports standard gRPC over HTTP/2
- Service/method granularity requires careful cardinality management
- Custom status codes (>16) are grouped under "unknown"
